The engine stays small.

j-harness reads agents from Markdown prompts and JSON blueprints, wires them into pipelines, and serves them over an async HTTP API. One Go binary, embedded SQLite, and any OpenAI-compatible endpoint you point it at.

Quickstart

# one line install (linux / macos)
curl -fsSL https://raw.githubusercontent.com/bigknoxy/j-harness/main/install.sh | sh

# run it against a local model
HARNESS_REGISTRY=~/.config/j-harness/registry harness --addr 127.0.0.1:8080

Prefer Docker? docker compose up --build starts the harness and an Ollama service together. Uninstall with curl -fsSL .../uninstall.sh | sh.

How it works

agent-registry/
  blueprints/*.json   which prompt, model, params
  prompts/*.md        system prompt / persona
  pipelines/*.json    DAG of steps: agent steps + routers

Named IO

Steps declare inputs and outputs. Later steps reference them with a strict template grammar: {{ steps.triage.output }}.

Routing

A router step picks one branch using conditions on JSON output: equals, not_equals, in, matches, exists.

Async by default

Submitting a job returns 202 with a session id. Poll the session for status, result, and per-step timing and tokens.

Boring state

Jobs and step results live in embedded SQLite with WAL. No broker, no daemon to babysit. The store sits behind an interface.

HTTP API

MethodPathPurpose
GET/healthzliveness
GET/readyzreadiness
POST/v1/agents/{id}/executesubmit an agent run, returns 202
POST/v1/pipelines/{id}/executesubmit a pipeline run, returns 202
GET/v1/sessions/{id}poll status and result
GET/v1/sessions/{id}/stepsper-step results
 
SESSION=$(curl -s -X POST localhost:8080/v1/agents/generic_agent/execute \
  -H 'Content-Type: application/json' \
  -d '{"input_data":"Say hello in five words."}' | jq -r .session_id)

curl -s localhost:8080/v1/sessions/$SESSION
